# World Line — 文明政權合法性模型比較（M4 世界史 grill-me 參考素材）

> **用途**：這不是現行技術/schema 決策，是**留給 M4（世界史階段）規劃時走 grill-me 用的參考素材**。M1/M2（中國史）不受本文件影響，不需要因為這份文件回頭改 schema。
> 非正式文件（不是憲法、不是 ADR、不是 PRD），不寫入 `.claude/constitutions/world-line.md`。
> 來源：使用者 2026-08-28 提供的四文明政權邏輯梳理，經與現有 M1 schema（`.claude/prds/world-line.md` §6）逐項比對後補充分析。

---

## 為什麼會有這份文件

`regimes.status`/`origin_transition_type` 原本直接存憲法 §4 的中文術語（存續/分裂/被取代(禪讓)/被滅亡），套用的心智模型是中原「天命觀／朝代週期」。使用者提出疑慮：這套邏輯若原封不動套到羅馬、歐洲封建、伊斯蘭世界，資料模型會不會碰壁？2026-08-28 已將 `status`/`origin_transition_type` 改為文化中立代碼（`active`/`split`/`succeeded`/`conquered`），憲法本身業務詞彙不變（見 PRD §6 設計原則、implementation plan 第四次事後補充）。這份文件記錄當時逐一比對四大文明後的結論，供 M4 規劃時延續。

## 一、使用者原始整理：四大文明政權底層邏輯

### 1. 中原文明：天命觀與「朝代週期（Dynastic Cycle）」

- **核心合法性來源**：「天命（Mandate of Heaven）」與「德」。
- **政權本質**：天下唯有一主（天子）。政權是有壽命的（朝代興衰），失德則天命轉移。
- **權力轉移形式**：
  - 暴力革命（湯武革命）：武力推翻前朝（如秦滅六國、漢滅秦）。
  - 形式合法移轉（禪讓）：權臣架空後，逼前朝「自願讓位」以承接正統（如漢禪魏、魏禪晉、宋受後周禪）。
- **在 GIS 上的特徵**：通常有清晰的「朝代起訖年代」，邊界是中央朝廷朝貢體系或直接設郡縣的實質管轄。

### 2. 古羅馬與拜占庭：元首共和遺緒與「軍事擁立」

西方（羅馬體系）完全沒有「禪讓」概念，因為羅馬本質上從未自稱是「私家天下的王朝」。

- **核心合法性來源**：「元老院與羅馬人民（SPQR）」的認可 + 軍隊效忠。
- **政權本質**：羅馬皇帝（Imperator/Augustus）在名義上是國家第一公民（Princeps）或最高統帥，而不是中原那種「承奉天命的家族」。皇位理論上不是私產，因此羅馬帝國在法律上是同一個國家持續了千年，學者劃分的「王朝（如塞維魯王朝、巴列奧略王朝）」只是現代歷史學為了方便標記哪個家族在掌權。
- **西方類似「讓位」的特例**：戴克里先退位（西元 305 年）——四帝共治時期，戴克里先主動退位隱居去種萵苣，並指定副手接班。這不是把天下送給另一個家族的「禪讓」，而是帝國官僚體系的職位交接。
- **權力轉移形式**：
  - 養子繼承（收養制）：五賢帝時期，皇帝不傳子，而是收養最有能力的將軍/執政官為嗣子。
  - 禁衛軍／軍團叛變（軍人政變）：軍隊殺掉前任皇帝，直接黃袍加身（拍賣皇位或軍營擁立）。拜占庭帝國有大量皇帝是靠刺瞎前任、送進修道院而登基的。

### 3. 中世紀歐洲封建：神授君權與「血統契約（采邑制）」

- **核心合法性來源**：天主教會加冕（神授） + 純粹的家族血統法則（如薩利克法）。
- **政權本質**：領土與爵位是貴族家族的私有財產與契約關係。「我附庸的附庸，不是我的附庸」。
- **沒有禪讓的原因**：國王不能把王位「讓」給外姓，因為王位是上帝賦予該血脈的法定繼承權。如果要換家族，只有兩種途徑：
  - 絕嗣（Extinction）：國王死後無合法男性後代，各國貴族依聯姻母系血統爭奪繼承權（因此引發英法百年戰爭、西班牙王位繼承戰爭）。
  - 教宗廢黜／貴族政變：如矮子丕平廢黜墨洛溫王朝末王（進修道院），獲得教宗加冕開啟卡洛林王朝。
- **在 GIS 上的特徵**：疆域極度破碎且常因婚姻/遺產分割而劇變（例如哈布斯堡家族靠結婚吃下半個歐洲；查理曼帝國死後直接被三個孫子切成三份，演變成德法意雛形）。

### 4. 伊斯蘭世界：哈里發體系與「烏瑪共識／部落推舉」

- **核心合法性來源**：先知穆罕默德的繼承者（哈里發 Caliph） + 伊斯蘭教法（Sharia）。
- **政權本質**：全體穆斯林社群（烏瑪 Ummah）的宗教與世俗領袖。
- **權力轉移形式**：
  - 推舉／協商（舒拉 Shura）：正統哈里發時期（四大哈里發），由長老會議推舉產生（非世襲）。
  - 家族世襲但伴隨血統內戰：伍麥亞王朝（白衣大食）、阿拔斯王朝（黑衣大食），雖然是家族世襲，但內部常以「誰的血統更接近先知家族（聖裔）」或宗教正統性發動聖戰推翻前朝。
  - 蘇丹架空哈里發：中後期塞爾柱土耳其、馬木路克興起，「蘇丹（世俗軍事統帥）」架空「哈里發（名義宗教領袖）」，類似日本幕府將軍架空天皇。

## 二、與現有 schema 逐項比對（2026-08-28 分析）

關鍵區分：**「政權層級的轉移」**（`regimes` 這個實體本身終止/誕生）vs **「統治者層級的更迭」**（政權不變，換了誰在位）。`regimes.status`/`origin_transition_type` 這個狀態機設計上只管前者；後者屬於敘事層級，落在 `historical_events`。用這條界線重新分類上表：

| 使用者描述的機制 | 層級 | 對應現有機制 | 需要新結構？ |
|---|---|---|---|
| 中原：禪讓、覆滅、分裂 | 政權層級 | `status`＝`succeeded`/`conquered`/`split` | 不需要，設計基礎案例 |
| 羅馬：戴克里先退位、養子繼承、軍團弒君 | 統治者層級（羅馬帝國本身沒變，只是誰在位變了） | `historical_events`（敘事），不動 `regimes` | 不需要 |
| 羅馬：395 東西羅馬分裂、476 西羅馬滅亡、1453 拜占庭滅亡 | 政權層級 | `split`／`conquered` | 不需要，直接對應 |
| 歐洲：矮子丕平廢梅羅文加、教宗敕封卡洛林 | 政權層級，性質接近禪讓（廢王送修道院而非處死） | `succeeded` | 不需要——這正是把「禪讓」改成中立代碼 `succeeded` 的價值所在：不同儀式（中國禪讓 vs 教宗敕封）都是「非武力政權更替」，中立代碼裝得下，原本的中文字面值裝不下 |
| 歐洲：查理曼帝國三分（凡爾登條約） | 政權層級 | `split` | 不需要，結構上等同 seed 資料的「漢→魏/蜀漢/吳」三分 |
| 歐洲：聯姻共主（哈布斯堡）、伊斯蘭：蘇丹架空哈里發 | **不是轉移，是兩個政權並存的持續關係** | `regime_relations`（已存在，`relation_type` 自由文字） | 不需要——這個關係跟日本幕府架空天皇是同一種資料形狀 |
| 伊斯蘭：舒拉推舉哈里發 | 統治者層級（哈里發國本身沒變） | `historical_events` | 不需要 |
| 伊斯蘭：阿拔斯革命推翻伍麥亞 | 政權層級，武力推翻 | `conquered` | 不需要 |
| 伊斯蘭：白衣大食/黑衣大食 | 命名機制 | `regime_aliases`——同一政權在不同時期/觀察者眼中的代稱，跟「阿拉伯帝國在唐朝視角下叫大食」同一種資料形狀 | 不需要，直接驗證既有設計 |
| 學者劃分的「王朝」（如塞維魯王朝）標記哪個家族在掌權 | 史學家敘事分期，非客觀政權分類 | `lineage_presets`（方案 D）——核心政權圖保持中立，「哪個家族在哪段時間主導」是史觀呈現層 | 不需要，這正是方案 D 存在的理由 |

### 結論：現有 M1 schema 不需要因此重新設計

四文明的差異，絕大部分落在「統治者如何產生」（Shura 推舉、養子繼承、軍團擁立、貴族血統）這個 `historical_events` 敘事層級能吸收的範圍，或是「兩個政權間的持續關係」（`regime_relations` 已支援）。真正會撞到「政權」這個實體邊界的轉移形式（分裂、武力推翻、和平轉移），中原案例已經涵蓋。

## 三、真正需要 M4 前處理的缺口

**與上一輪（文化偏頗檢視）已追蹤的缺口相同，未發現新的 schema 級缺口**：

- [ ] `predecessor_regime_id` 是單一 FK，只能表達「一對多分裂」，無法表達「多對一合併」。歐洲封建的聯姻共主如果後來正式合併成單一政權（例如英格蘭+蘇格蘭→大不列顛），會撞上這個缺口——哈布斯堡聯姻案例只是同一問題的另一個例證，不是新問題。詳見 PRD §9 風險表、§12「M4 前必須處理」。

## 四、值得記錄、但現在不用動的開放問題

**「政權身份」與「統治家族」現在焊在同一個 `regimes` 實體裡**：中國史剛好兩者重合（漢＝劉家，換家族＝換政權），不會碰到這個問題。羅馬／哈里發這種「政權本身連續存在千年，只是統治家族換了好幾輪」的情況，現有設計沒有獨立的「統治家族」概念。

- **是否需要為此開新表**：地圖層級（政權疆域）不需要這個資訊——羅馬帝國的疆域形狀不會因為換了個家族在位就改變。只有敘事層級（誰在哪段時間統治、哪個「王朝」標籤）需要，現階段用 `historical_events` 描述已經夠用，不必為了羅馬預先加表。
- **M4 grill-me 時再問**：如果實際建置羅馬/拜占庭資料時發現「哪個家族在位」這個資訊真的需要被查詢/篩選（不只是敘事文字），才需要評估要不要加一張類似 `reign_eras` 的「ruling house」查詢表。現在只是標記，不預先設計。
